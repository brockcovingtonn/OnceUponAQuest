# Once Upon a Quest — project brief for Claude Code

Read this file first in every session. Then read `docs/PRODUCT_SPEC.md`, `docs/WIREFRAMES.md` and `docs/BUILD_PLAN.md`.

## What this is
Once Upon a Quest is an **unofficial** fan app for theme park guests. Guests complete short quests at real park locations: they find hidden details, check in at each spot, and collect badges. Phase 1 is a pilot on one street (Main Street, U.S.A. at Disneyland Resort, Anaheim) with 20 spots in 4 quests.

Later phases (do NOT build yet): pin collection and trade matching, outfit closet, history audio tours, group meetups.

## Hard rules (legal and safety — never break these)
1. **Unofficial.** The app is not affiliated with, endorsed by, or sponsored by The Walt Disney Company. Show this disclaimer on the sign-in screen, in Settings, and in store listings:
   "Once Upon a Quest is an independent fan app. It is not affiliated with, endorsed by, or sponsored by The Walt Disney Company or its affiliates. All park names are used only to describe locations."
2. **No Disney IP in the app.** No Disney logos, fonts, character art, character names in UI chrome, Disney castle designs or the Disney castle logo, or three-circle head-and-ears shapes in the logo, icons, illustrations or store screenshots. Park and attraction names may appear only as plain text describing a location.
   - **Original castles:** original castle illustrations are allowed inside the app only (for example, quest art and empty states), never in the app logo, app icon, splash screen, or store screenshots and listings. Each one must: use an architecture style that is not a tall symmetrical cluster of slim spires; avoid pink-and-blue and blue-and-gold towers (use the brand palette); never appear with an arc, star or fireworks over it or next to Disney-style lettering; and pass the squint test — shrunk to a small silhouette, a fan should not recognize it as either Disney park castle. When in doubt, don't use a castle.
3. **Use the user's own photos** (and the founder's own field photos) for spot images. Never pull images or text from websites or books.
4. **No commercial activity on park property.** No buying, selling, paid bookings, or paid in-person services arranged through the app.
5. **Guest safety.** Never tell users to stand in the street, block doorways, or run. Spots flagged `pause_during_parades` must show a "Paused during parades and fireworks — check back after" banner when the user sets Parade mode on.
6. **Answer keys never reach the client.** Answers live in the `private` schema and are checked only by the `check_in` database function.
7. **Ages 13+** in Phase 1 (age gate at onboarding). Any future social or meetup feature is 18+.

## Tech stack
- **App:** Expo (React Native) with Expo Router, TypeScript (strict). One codebase for iOS and Android.
- **Backend:** Supabase (Postgres, Auth, Storage, RPC functions). Schema is in `supabase/migrations/`, seed in `supabase/seed.sql`.
- **Auth:** Supabase email one-time code (no passwords in Phase 1).
- **Device:** `expo-location` (foreground only), `expo-image-picker` (camera), `expo-haptics`.
- **State/data:** `@tanstack/react-query` for server data; React state for UI. No Redux.
- **Styling:** React Native `StyleSheet` with tokens in `src/theme/`. No UI kit dependency.
- Prefer Expo SDK packages over community ones. Check current Expo docs before choosing package versions.

## Brand (original — no Disney look-alikes)
- Colors: Midnight `#1B2340` (primary/background on dark), Storybook Gold `#E2B04A` (accent, badges), Parchment `#FAF5EA` (light background), Ink `#2A2A33` (text on light), Rose `#D9677A` (errors/alerts), Fern `#4F9D7A` (success).
- Type: "Fraunces" for headings, "Inter" for body (both Google Fonts, open license) via `expo-font`.
- Visual motif: storybook pages and passport stamps. Badges are round stamps with original illustrations (lamp, window, envelope, chili bowl), never characters.

## Conventions
- TypeScript strict; no `any`. Generate DB types after every migration.
- Every screen handles loading, empty and error states.
- All copy in `src/copy.ts` so it can be reviewed in one place.
- Accessibility: every touchable has an accessibility label; text scales with system font size; minimum 44pt touch targets.
- Commit after each build-plan step with a message naming the step.
- When unsure about a product decision, ask instead of guessing.
